# LLM-Assisted Regex Audit Infrastructure

An offline, deterministic, and privacy-preserving workflow for discovering and critiquing technical skill regular expressions and tag aliases from European job posting descriptions.

---

## 1. Core Architectural Principles

1. **Zero Monetary Cost & Local Inference:** All inference runs exclusively on the local machine via [Ollama](https://ollama.com/) utilizing the NVIDIA GeForce RTX 4060 Laptop GPU. No external APIs, hosted services, or paid subscriptions are used.
2. **Deterministic Extraction Intact:** The production skill extraction pipeline in `src/analytics.py` and `app.py` remains 100% deterministic Python code. The LLM acts strictly as an offline rule-critique assistant; it **never** classifies production postings directly.
3. **No Automatic Adoption:** Candidate proposals generated by the model are never automatically accepted. Every candidate undergoes independent static and adversarial safety checks, synthetic unit test assertions, full-corpus differential evaluation with hard timeouts, and blind holdout validation.
4. **Strict Benchmark Isolation (Zero Leakage):** Human-annotated holdout benchmarks (`r_validation.xlsx`, `spike_validation.xlsx`) are strictly separated into `BenchmarkSnippet` objects and excluded from prompt construction. The prompt builder only accepts `DiscoverySnippet` instances.

---

## 2. Local Setup & Hardware Configuration

- **Inference Runtime:** Ollama (version ≥ 0.40) running locally on `http://127.0.0.1:11434`.
- **Target Hardware:** NVIDIA GeForce RTX 4060 Laptop GPU (8 GB VRAM), CUDA 12.9, compute capability 8.9.

## 3. Running the Discovery Pilot

The pilot can be executed programmatically or via the orchestration script:

```python
from analysis.llm_regex_audit import (
    load_benchmark_datasets,
    sample_discovery_snippets,
    verify_discovery_sample,
    run_skill_pilot,
)
from src.analytics import load_skills_vocabulary
import json

# 1. Load vocabulary and raw corpus
vocab = load_skills_vocabulary()
with open("data/raw/freehire_eu_raw.json", encoding="utf-8") as f:
    postings = json.load(f)

# 2. Extract benchmark IDs to guarantee zero leakage
benchmark_ids, r_benchmarks, excel_benchmarks = load_benchmark_datasets()

# 3. Sample ~50 stratified discovery snippets (excluding all benchmark IDs)
r_discovery = sample_discovery_snippets(
    postings, "R", vocab,
    seed=20261030,
    current_hits_n=20,
    near_miss_n=20,
    negative_controls_n=10,
    excluded_posting_ids=benchmark_ids,
)
verify_discovery_sample(r_discovery, benchmark_ids)

# 4. Run pilot
r_result = run_skill_pilot(
    "R", vocab, postings, r_discovery, r_benchmarks, model_name="qwen3:4b"
)
```

## 5. How to Inspect Reports and Make Decisions

Each generated Markdown report contains 7 distinct audit sections:
1. **Candidate Proposal Overview:** The proposed regex, aliases, confidence score, and technical rationale.
2. **ReDoS & Syntactic Safety Analysis:** Static nested repetition checks and adversarial timeout assertions.
3. **Synthetic Test Suite Results:** Unit test passes/failures on positive and negative test phrases.
4. **Corpus Posting-ID Differential Impact:** Exact counts for Current Hits, Candidate Hits, Shared Hits, Current-Only (lost production hits), and Candidate-Only (new discoveries).
5. **Human-Confirmed Benchmark Validation:** Precision and recall evaluated strictly on verified human holdouts (reports `N/A` if denominators are zero).
6. **Sample Candidate-Only Excerpts:** Real job posting snippets where the candidate pattern matched but the production regex did not.
7. **Identified Risks & Expert Review Decision:** Highlighted failure modes, ambiguities, and production regression warnings.

---

## 6. How to Approve a Candidate (Future Phase)

If an audited candidate passes all checks and is approved by a human domain expert:
1. Review the candidate-only snippets to confirm they represent genuine technical skill requirements.
2. Confirm that the `current_only` set is empty or that dropped detections are verified true false-positives.
3. Add any proposed aliases to the skill entry in `data/fixtures/skills_vocabulary.json`.
4. Update the `regex` field in `data/fixtures/skills_vocabulary.json`.
5. Run the full test suite (`pytest`) and update `PLANNING_LOG.md`.
6. Regenerate `analytics_summary.json` and `.postings_cache.json`.

## 7. Deterministic Evaluation, Timeout Audit & Reproducibility (Phase 4 & 5)

All evaluation and audit tooling runs entirely locally with zero external network access and zero inference cost.

### Reproducibility Commands

1. **Run Dedicated Audit Tests (38 tests):**
   ```bash
   uv run pytest tests/test_llm_regex_audit.py tests/test_llm_regex_audit_client.py
   ```
   *Ollama requirement:* Not required (LLM client calls are mocked in unit tests).

2. **Run Full Repository Test Suite (390 tests):**
   ```bash
   uv run pytest
   ```
   *Ollama requirement:* Not required.

3. **Re-Run Multi-Factor Timeout Audit:**
   ```bash
   uv run python -m analysis.llm_regex_audit.audit_timeout
   ```
   *Ollama requirement:* Not required. Evaluates compilation, 500-sample search, 25k in-process search, Windows spawn/IPC, and worker execution times across 4 benchmark patterns. Saves results to `analysis/llm_regex_audit/artifacts/timeout_audit_measurements.json`.

4. **Re-Run Deterministic Baseline Evaluation:**
   ```bash
   uv run python -u -m analysis.llm_regex_audit.phase4_baseline_runner
   ```
   *Ollama requirement:* Not required. Precomputes baseline hits in parent process, runs 6 deterministic candidates across 25,394 postings with isolated worker processes and blind holdout benchmarks, and regenerates `phase4_deterministic_baseline_results.json` and `phase4_deterministic_baseline_report.md`.

5. **Regenerate Phase 4 Reports (Instant, no re-evaluation):**
   ```bash
   uv run python -c "import json; from analysis.llm_regex_audit.phase4_baseline_runner import generate_phase4_markdown_report, ARTIFACTS_DIR; res = json.load(open(ARTIFACTS_DIR / 'phase4_deterministic_baseline_results.json', encoding='utf-8')); generate_phase4_markdown_report(res, {})"
   ```
   *Ollama requirement:* Not required.
